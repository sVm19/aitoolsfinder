# API Specification

## 1. Conventions
- Base path: `/api/v1`
- JSON request and response bodies.
- OpenAPI generated by FastAPI.
- UTC timestamps in ISO 8601.
- UUID identifiers.
- Consistent error envelope.
- Pagination: `page` (default 1), `page_size` (default 20, max 100).
- Public GET endpoints may be unauthenticated.
- Protected endpoints require validated Cognito bearer token.

## 2. Standard response patterns

List:
```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0,
  "total_pages": 0
}
```

Error:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request could not be processed.",
    "request_id": "..."
  }
}
```

## 3. Public catalog endpoints
- `GET /tools` — search and filter tools
- `GET /tools/{slug}` — published tool detail
- `GET /categories` — active categories
- `GET /categories/{slug}` — category and associated tools
- `GET /tags` — tags
- `GET /tags/{slug}` — tools by tag
- `GET /tools/{slug}/alternatives` — alternatives
- `GET /rankings` — published rankings
- `GET /search` — search tools

Suggested filters:
`q`, `category`, `tags`, `pricing_model`, `platform`, `sort`, `page`, `page_size`.

## 4. Comparison endpoints
- `GET /comparisons/{slug}` — public comparison
- `POST /comparisons` — create user comparison (authenticated if saved)
- `POST /comparisons/preview` — compare selected published tool IDs without saving

## 5. Identity and user endpoints
- `GET /users/me`
- `PATCH /users/me`
- `GET /users/me/saved-tools`
- `POST /users/me/saved-tools/{tool_id}`
- `DELETE /users/me/saved-tools/{tool_id}`

## 6. Vendor and submission endpoints
- `POST /submissions` — submit a tool
- `GET /vendors/me`
- `PATCH /vendors/me`
- `GET /vendors/me/submissions`

Submissions must be moderated before public publication.

## 7. Admin endpoints
- `POST /admin/tools`
- `PATCH /admin/tools/{tool_id}`
- `DELETE /admin/tools/{tool_id}` (prefer archive over destructive delete)
- `POST /admin/tools/{tool_id}/publish`
- `POST /admin/tools/{tool_id}/verify`
- CRUD endpoints for categories, tags, features and pricing plans
- `GET /admin/submissions`
- `POST /admin/submissions/{submission_id}/approve`
- `POST /admin/submissions/{submission_id}/reject`

All admin endpoints require server-side admin authorization and audit logging.

## 8. AI endpoints
- `POST /recommendations` — accept a user goal and constraints; return ranked tool candidates with reasons and limitations.
- `POST /recommendations/feedback` — capture helpful/not-helpful feedback.

Do not allow the model to invent tools, prices, features or scores. Recommendations must be grounded in catalog records and include tool IDs and evidence fields.

## 9. Payment and webhook endpoints
- `POST /payments/checkout` — create checkout session after provider capability verification.
- `POST /webhooks/tiun` — verify provider signature and process event idempotently.
- `GET /subscriptions/me` — current subscription status.

Treat provider webhooks as authoritative for payment state. Verify signatures, deduplicate event IDs and safely handle retries. Do not implement guessed Tiun request fields; use the provider's current official API documentation.

## 10. Health endpoints
- `GET /health/live`
- `GET /health/ready`

## 11. Security requirements
- Validate all inputs with Pydantic.
- Enforce rate limits on search, auth-adjacent and AI endpoints.
- Set request size limits.
- Restrict CORS to known origins.
- Validate outbound destinations to prevent open redirects and SSRF.
- Do not expose internal exception details in production.
- Add request IDs and structured logs.
